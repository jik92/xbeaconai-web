# 千川 PC 商品短视频投放设计

## 目标

在烽火AI中新增“投放”菜单，并提供“千川商户绑定”和“千川PC投放”两个页面，打通代理商 OAuth 授权、商户与投放账户选择、商品短视频素材上传、PC 计划组/计划/创意创建、审核状态管理和投后报表。

第一期不实现直播间推广、随心推、全域推广、自动追加预算或自动起量。

## 导航与页面

侧边栏新增一级分组“投放”：

- 千川商户绑定
- 千川PC投放

商户绑定页展示 APP 配置状态、OAuth 授权入口、已授权主体、店铺、投放账户、Token 状态和默认投放账户。任何 Secret 或 Token 均不返回前端。

PC 投放页提供账户选择、商品与抖音号查询、本地素材选择、千川素材上传、投放参数编辑、真实写入确认、投放列表、审核状态与报表。

## 凭据与 OAuth

全局应用凭据复用现有 AES-256-GCM 密钥管理：

- `QIANCHUAN_APP_ID`
- `QIANCHUAN_APP_SECRET`

对话中暴露的旧 Secret 不进入代码、文档、日志或提交。管理员轮换 Secret 后在密钥管理页面录入。

OAuth Token 按烽火AI用户和授权主体单独加密持久化，包括 access token、refresh token、到期时间、授权用户、主体、店铺和默认投放账户。

OAuth state 由服务端签名，十分钟有效，只能消费一次，并绑定当前烽火AI用户。回调地址使用 `https://api.xbeaconai.com/callback`。

## 投放数据流

1. 用户完成代理商 OAuth 授权。
2. 系统查询授权主体、商户、店铺及关联的 `advertiser_id`。
3. 用户选择默认投放账户。
4. 页面查询可投商品和已授权抖音号。
5. 用户从烽火AI素材库选择视频和封面。
6. Worker 将素材上传到目标千川账户，并保存本地素材与上游素材 ID 映射。
7. 用户编辑计划组、计划、创意和基础定向。
8. API 校验账户、商品、素材、预算、出价/ROI、日期和时段，生成短期确认令牌。
9. 用户再次确认后创建本地投放记录，Worker 依次创建计划组、计划和创意。
10. Worker 同步审核与启停状态，并按日期同步账户、计划和素材报表。

## 投放参数

第一期支持：

- 计划组名称或选择已有计划组
- 计划名称
- 商品
- 已授权抖音号
- 视频素材、封面和创意标题
- 推广目标与优化目标
- 日预算
- 出价或目标 ROI
- 投放开始与结束时间
- 投放时段
- 地域、性别和年龄基础定向

所有投放对象默认以暂停状态创建。如果上游接口不支持安全地创建为暂停状态，系统必须阻止真实提交并提示用户，不能自动开启消耗。

## 数据模型

新增：

- 千川 OAuth 绑定
- 授权主体、店铺与投放账户
- 本地素材与千川素材映射
- PC 投放草稿
- 计划组、计划与创意记录
- 每日报表快照
- OAuth state
- 真实投放确认令牌和幂等记录

所有资源以烽火AI用户、绑定关系和投放账户联合隔离，不信任前端提交的 owner、主体或账户身份。

## 进程职责

API Server 负责 OAuth、配置状态、商户与账户查询、投放草稿校验、确认令牌、幂等控制以及投放与报表读取。

Worker 负责 Token 刷新、素材上传、计划组/计划/创意创建、审核状态同步和报表同步。Worker 更新的状态必须回写 SQLite。

## 状态与错误

- Token 过期前自动刷新；刷新失败后标记为需要重新授权。
- 素材映射以本地素材、投放账户和内容标识幂等。
- 创建链路保存每一级上游 ID，恢复时先查询已有状态，避免重复创建。
- 权限、账户、余额、商品、素材和参数错误不重试；限流和暂时性网络错误有限退避。
- 保存上游 `request_id` 和脱敏错误，不保存 Secret、Token、授权码或带敏感查询参数的 URL。

## 真实消耗保护

创建、启用、修改预算等操作均属于真实外部写入，必须由用户显式确认。第一期不自动启用、不自动追加预算、不自动续期、不自动起量。

## 报表

支持账户、计划和素材三级数据，按日保存消耗、曝光、点击、点击率、成交金额、订单数、转化成本和 ROI。报表支持日期筛选、后台定时同步和手动补拉。

## 验证约定

按用户明确要求，本次不运行测试、E2E、类型检查或生产构建。交付时必须将代码标记为未验证，并列出上线前需要执行的验证和真实账户冒烟步骤。

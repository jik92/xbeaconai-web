# 本地 BullMQ 工作区隔离修复设计

## 问题

多个本地工作区使用相同 Redis 和 `REDIS_QUEUE_NAME=yaozuo-jobs`。其他工作区的 Worker 会抢到当前工作区任务；由于它连接的是另一份 SQLite，找不到任务后直接返回，BullMQ 将任务标记完成，而任务所属数据库仍停留在“排队中”。

## 已确认方案

- 生产环境继续严格使用显式 `REDIS_QUEUE_NAME`，不改变 Server/Worker 部署契约。
- 开发环境在配置的队列基础名后追加由绝对数据目录生成的稳定短哈希。同一工作区的 Server 和 Worker 使用同一数据目录，因此仍能协作；不同工作区自动隔离。
- 增加单元测试，证明同一目录稳定、不同目录隔离、生产名称不变。
- 停止当前已确认的冲突工作区进程，重启当前开发进程使新队列生效，再从 SQLite 恢复并重新投递卡住任务。

## 验证

- 检查目标任务由 `queued` 进入 `processing` 或终态，且 `updated_at` 发生变化。
- 确认新 BullMQ 队列只由当前工作区 Worker 消费。
- 运行队列命名单测、相关 Worker 测试、类型检查和生产构建。

# 巨量千川随心推接入设计

## 目标

在烽火AI中新增“投放”菜单，并提供“巨量千川绑定”和“千川随心推”两个页面，打通代理商自研投放系统的 OAuth 授权、素材上传、短视频带商品随心推订单创建、订单状态查询与投后报表同步。

第一期严格限定为当前应用已获批的“千川随心推”能力，不实现千川 PC 竞价、全域推广、直播间随心推、自动续费或自动增加预算。

## 导航与页面

侧边栏新增一级分组“投放”，包含：

- 巨量千川绑定
- 千川随心推

“巨量千川绑定”页面展示应用配置状态、OAuth 授权入口、当前授权用户、店铺或代理商主体、关联投放账户、Token 状态和默认投放账户。Secret 和 Token 永不返回明文。

“千川随心推”页面提供素材选择与上传、可投商品和抖音号选择、订单参数编辑、真实消耗确认、订单列表、状态同步和日期范围报表。

## 凭据与授权

全局应用凭据复用现有 AES-256-GCM 密钥管理：

- `QIANCHUAN_APP_ID`
- `QIANCHUAN_APP_SECRET`

APP ID 是非敏感配置；APP Secret 必须由管理员在轮换后通过密钥管理录入。对话中暴露的旧 Secret 不写入源码、文档、迁移、日志或提交。

OAuth Token 不是全局 Provider Key。系统新增按烽火AI用户和授权主体隔离的绑定记录，加密保存：

- `access_token`
- `refresh_token`
- Token 到期时间
- 授权用户标识
- 主体类型和主体标识
- 默认投放账户

OAuth `state` 由服务端生成、签名、短期有效且只能消费一次，并绑定发起授权的烽火AI用户。回调地址使用 `https://api.xbeaconai.com/callback`。回调处理器使用授权码换取 Token，再查询授权用户、主体和投放账户关系。

## 数据模型

新增四组持久化数据：

1. 千川授权绑定：所属用户、上游授权用户、主体、加密 Token、到期时间、授权状态、默认账户。
2. 千川投放账户：绑定关系、`advertiser_id`、账户名称、账户类型和同步时间。
3. 千川素材映射：本地素材、投放账户、上游素材 ID、素材类型、上传状态、上游请求 ID和错误摘要。
4. 随心推订单及报表：本地订单、上游订单 ID、参数快照、状态、审核信息、消耗确认信息，以及按日期和维度保存的报表快照。

所有查询必须同时校验烽火AI用户和绑定关系，不信任前端提交的 owner、主体或账户身份。

## API 与异步任务

API Server 负责：

- 返回应用配置和绑定状态
- 生成 OAuth 授权 URL
- 处理 OAuth callback
- 查询和更新默认投放账户
- 创建本地素材上传任务
- 校验随心推订单草稿并要求显式确认
- 创建本地订单任务
- 查询订单、状态和报表

Worker 负责：

- 刷新即将过期的 OAuth Token
- 上传图片、视频或图文素材
- 查询可投抖音号、商品和视频
- 创建随心推短视频带商品订单
- 查询订单详情、审核与投放状态
- 同步随心推订单数据

所有上游请求保留 `request_id` 和脱敏后的请求摘要。Secret、Token、授权码和带凭据的 URL 参数不进入日志与审计响应。

## 真实消耗保护

创建订单属于真实付费动作。前端提交前必须展示投放账户、商品、素材、预算、投放时间、优化目标和出价或 ROI，并要求用户主动确认。

后端使用一次性确认令牌和幂等键，防止页面重复提交或网络重试创建多笔订单。第一期不自动续费、不追加预算、不自动开启起量。

## 错误与恢复

- Token 失效时将绑定标记为需要重新授权，不静默切换账户。
- 上游限流和暂时性错误可按有限退避重试；参数、权限、余额和审核错误直接持久化并展示。
- 素材上传以本地素材、投放账户和内容指纹保证幂等。
- 订单创建先保存本地记录，再由 Worker 提交；进程恢复后根据幂等键和上游订单查询避免重复投放。
- 报表同步保留最近成功时间，并允许用户手动触发补拉。

## 验证约定

本次按用户明确要求不运行测试、E2E、类型检查或生产构建。实现仍补充必要的单元和集成测试代码，但交付状态必须明确标记为未执行验证，待上线前运行仓库规定的验证命令。

# 一键成片素材版本、配音替换与字幕合成设计

## 目标

让每个分镜的视频素材具备完整、可回退的版本历史，并把配音替换和字幕合成变成明确的行级加工动作。任何
AI 生成、手动替换或后处理结果都不能覆盖旧素材；用户可以预览历史中的成功版本并重新应用。

## 核心模型

- 为分镜增加独立的不可变素材版本记录，来源分为 `ai_generated`、`library_replacement`、
  `upload_replacement`、`audio_replaced` 和 `subtitle_composed`。
- 每条版本记录保存所属分镜、来源、底层内容引用、生成状态、输入版本、关联任务、错误和创建时间。
- 分镜保存当前应用版本 ID。切换历史只更新当前指针，不复制文件、不删除版本，也不改变历史顺序。
- 历史记录必须经过项目和分镜的 owner 校验；服务端不接受前端提交的 owner ID。
- 最终合并始终从每个分镜的当前应用版本解析视频输入。

## 加工顺序与一致性

- 【配音替换】以点击时的当前视频版本和当前配音产物为输入，创建独立异步任务。成功后新增
  `audio_replaced` 版本并自动应用。
- 【字幕合成】以点击时的当前视频版本和当前字幕时间轴为输入，创建独立异步任务。成功后新增
  `subtitle_composed` 版本并自动应用。
- 两种加工都锁定提交时的输入版本。先配音再字幕时，字幕任务处理配音替换后的版本；反向操作时，配音任务
  处理已经烧录字幕的视频。
- 同一分镜同一时间只允许一个视频生成或加工任务，避免较晚完成的旧任务覆盖新选择；不同分镜可以并行。
- 幂等键重复提交返回原任务。失败只更新对应历史记录，当前应用版本保持不变。

## 手动替换与 AI 生成

- AI 视频生成成功后新增 `ai_generated` 版本并自动应用，不再直接覆盖唯一视频引用。
- 从素材库选择的视频新增 `library_replacement` 版本；本地上传完成后新增 `upload_replacement` 版本。
- 手动替换也保留原始素材引用，因此可以在历史中预览并重新应用。
- 迁移现有分镜时，为已有视频建立兼容版本并设为当前版本；没有视频的分镜不创建空版本。

## 界面

- 每行素材 Cell 增加【生成历史】按钮，与 AI 生成、素材库、本地上传保持同一紧凑操作区。
- 每行配音 Cell 增加【配音替换】。没有当前视频、没有配音产物或该分镜正在处理时禁用。
- 每行字幕 Cell 增加【字幕合成】。没有当前视频、没有字幕时间轴或该分镜正在处理时禁用。
- 加工中仅当前分镜相关按钮显示加载状态，当前素材继续可预览，其他分镜仍可操作。
- 【生成历史】使用标题式 shadcn Dialog，展示版本预览、来源、创建时间、状态和失败原因。
- 成功版本提供【应用此版本】，当前版本显示“使用中”；生成中和失败版本不可应用。
- 应用历史成功后立即刷新素材预览，后续加工以新应用版本为输入。
- 继续遵循 `DESIGN.md` 的白色紧凑表格、hairline 分隔、`h-8` 控件和 pill 按钮，不新增副标题或页面专属 CSS。

## API、任务与存储

- 新增分镜素材版本表和对应 Drizzle migration；分镜增加当前版本外键或等价的可空引用。
- 项目响应返回当前版本摘要；历史通过分镜级分页或有界列表接口按创建时间倒序读取。
- 新增应用历史版本接口，并为配音替换、字幕合成增加受保护的任务提交接口。
- 队列消息只保存项目、分镜、输入版本和操作类型；真实状态仍以 SQLite 为准。
- Worker 复用现有 FFmpeg、artifact、任务进度和取消机制，生成成功后原子写入版本并切换当前指针。
- API 契约变化后重新导出 OpenAPI 并生成前端 SDK，禁止手工修改生成文件。

## 错误处理

- 输入版本已不再是当前版本、音频或字幕缺失、素材不可读时返回结构化且不可重试的业务错误。
- Provider、FFmpeg 或文件写入失败时记录安全化错误，不暴露本地路径、签名 URL 或凭据。
- 应用历史前再次校验版本属于当前账号、项目和分镜，且版本状态为成功、内容仍可用。
- 历史版本的底层内容不可用时允许查看记录和错误，但禁止应用。

## 验证

- Store 与数据库测试覆盖迁移、五类来源、当前指针切换、失败回退和 owner 隔离。
- API 测试覆盖历史读取、应用版本、两个加工任务、幂等和同分镜并发保护。
- Worker 测试覆盖锁定输入版本、配音替换、字幕烧录、成功自动应用及失败保留当前版本。
- 前端测试覆盖按钮位置、禁用条件、加载状态、历史预览与应用状态。
- 运行相关单测、`make ci`、`bun run db:check`、`bun run typecheck` 和 `bun run build`；按仓库规则不运行 E2E。

# 脚本二创虚拟人像降级设计

## 目标

当 Seedance 因参考图可能包含真人而返回 `InputImageSensitiveContentDetected.PrivacyInformation` 时，在不修改用户原始素材的前提下，用虚拟人像替换参考图中的脸，并自动重试一次视频生成。

## 产品交互

- 【上传配置】增加虚拟人像设置，优先允许用户从现有系统虚拟人像库选择。
- 用户可不选择；发生真人隐私拦截时，系统自动生成一个成年、无公众人物特征、无现实身份指向的虚拟脸。
- 原始分镜参考图、商品图和素材库文件保持不变。
- 任务结果明确记录是否使用了虚拟人像降级，禁止静默替换。

## 数据流

1. 分镜生成和首次 Seedance 提交继续使用原参考图。
2. Worker 仅在 Ark 明确返回真人隐私错误时进入降级流程。
3. Worker 使用 `gpt-image-2` 创建任务级安全参考图：保持商品、服装、动作、构图、背景、光影和画幅，只替换人物面部身份。
4. 若用户选择系统虚拟人像，将原分镜图与虚拟人像图共同作为编辑参考；否则由模型创建无现实身份指向的成年虚拟脸。
5. 安全参考图作为临时任务产物上传，替换触发审核的首张分镜参考图，再向 Seedance 重试一次。
6. 无论成功或失败，都不覆盖原素材；暂存文件沿用任务清理机制。

## 错误与重试

- 只匹配 Ark 错误码 `InputImageSensitiveContentDetected.PrivacyInformation`，其他 400 错误保持原行为。
- 每个任务最多执行一次换脸和一次 Seedance 重试，避免无限循环与不可控费用。
- 安全图生成失败时返回结构化错误，同时保留原始 Ark 拦截原因。
- 第二次提交仍被拦截时返回明确的虚拟人像降级失败信息。
- Ark 的内容政策无法也不应被规避；该流程只通过无现实身份指向的虚拟人物提供合规替代输入。

## 实现边界

- 前端复用现有系统人像选择能力，不建立第二套人像库。
- API 在脚本二创根项目中保存可选的系统人像引用，并在分镜视频子任务中传递。
- Worker 集中处理隐私错误识别、安全图生成、引用替换、重试和 provenance，Ark Provider 保持通用请求职责。
- 不更改原始参考图，不进行真人身份仿冒，不提供绕过审核的开关。

## 验证

- 单元测试覆盖错误码识别、仅重试一次、选定虚拟人像与自动虚拟脸两条路径、其他 Ark 400 不降级、原引用不变。
- API/Worker 隔离测试覆盖配置传递和 provenance。
- 真实测试先调用 `gpt-image-2` 生成安全副本，肉眼核对除脸外的商品与构图保持情况；再向真实 Seedance 提交并确认任务创建不再触发真人隐私错误。
- 完成相关格式检查、单元测试、类型检查和生产构建；不运行 E2E。

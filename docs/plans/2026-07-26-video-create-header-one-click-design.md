# 一键成片统一 Header 与全流程生成设计

## 目标

将“一键成片”工作台调整为统一 Header 加下方两栏的页面结构，并提供新建、草稿、历史与真正的一键全流程生成入口。

## 页面布局

- 页面最上方使用一个横跨整页的 52px Header，左侧只显示“新建项目”。
- Header 右侧依次显示“一键生成”“保存草稿”“生成记录”“新建”。
- “一键生成”使用主按钮；其余操作使用次级或幽灵按钮，不新增说明性文案。
- Header 下方保留现有两栏工作台：左侧参数配置，右侧脚本与分镜产出。
- 移除左栏原有标题和“新建”，并移除右栏重复的“生成记录”。右栏继续保留脚本与分镜切换。
- 窄屏时 Header 保持独立于两栏内容，操作区允许横向滚动，避免按钮挤压标题。

## 按钮行为

- “保存草稿”持久化当前输入；允许没有产品图片，首次保存会创建项目，后续保存更新同一项目。
- “一键生成”要求至少一张产品图片，保存当前输入后启动从分析到最终成片的完整流程。
- “生成记录”打开现有历史抽屉。
- “新建”清空当前编辑态并创建新的空白上下文，不删除已有项目或生成记录。
- 有运行中任务时禁用会产生冲突的保存、生成与新建操作，并显示真实运行阶段。

## 一键生成流程

采用项目级持久化编排，而不是由浏览器逐个调用接口：

1. 分析产品与输入参数。
2. 生成脚本。
3. 生成分镜。
4. 按当前媒体设置生成全部分镜视频，并按分镜开关生成配音和字幕。
5. 所有必需素材就绪后合并最终成片。

每个阶段继续复用现有 BullMQ Job 和 SQLite 状态。项目保存自动流程状态与当前阶段；Worker 完成一个阶段后推进下一阶段，因此刷新或关闭页面不会中断。已成功阶段不重复执行，失败时保留真实错误并允许重新触发未完成阶段。

## 契约与安全边界

- API 增加明确的全流程动作，不把多阶段调度隐藏在前端。
- 草稿创建放宽产品图片前置校验，但一键生成继续在服务端校验至少一张产品图片。
- 沿用现有 Bearer Token、owner 隔离、结构化错误、任务幂等和 Provider 来源标记。
- API 契约变化后重新导出 OpenAPI 并生成前端 SDK，不手工修改生成文件。

## 验证

- 单元测试覆盖空图片草稿、全流程动作校验、阶段推进、失败恢复、重复投递和完成状态。
- 前端结构测试覆盖统一 Header、按钮集合与被移除的重复入口。
- 运行相关单测、API/SDK 生成、`make ci`、`bun run typecheck` 和 `bun run build`。
- 按仓库约定不运行 E2E。

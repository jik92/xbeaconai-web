# 共享项目记录抽屉设计

## 目标

将“爆款二创”的项目记录与“一键成片”的生成记录统一为同一套紧凑设计语言和功能模型。两边共享布局、交互状态与基础组件，同时保留各自的业务字段和项目恢复逻辑。

## 设计原则

- 使用一个共享记录抽屉，不复制两套结构或样式。
- 抽屉采用紧凑右侧布局，桌面端最大宽度为 `max-w-lg`，小屏占满可用宽度。
- 标题栏固定为 52px，只显示中文主标题与关闭按钮。
- 所有文字使用语义化 `type-*` Token：项目标题 14px，状态、摘要、时间与操作 12px。
- 复用现有 `Button`、`Input`、`NativeSelect`，不引入新依赖或业务专属基础控件。
- 功能必须连接真实接口；不以仅前端过滤或临时状态伪装服务端能力。

## 共享组件

新增 `ProjectRecordDrawer`，负责：

- 遮罩、焦点区域、关闭行为和响应式抽屉外壳。
- 搜索输入、状态筛选和筛选重置。
- 加载、空数据、错误与重试状态。
- 紧凑记录行、当前项目标识、内联重命名和继续创作操作。
- 已加载数量、总数和“加载更多”分页操作。

共享组件接收标准化记录模型和回调，不直接依赖爆款二创或一键成片的 API 类型。业务页面负责把项目映射为统一的 `id`、`title`、`status`、`summary`、`updatedAt` 和可选创建者信息，并提供查询、重命名与打开项目的动作。

## 布局

抽屉从上到下分为四个区域：

1. 52px 标题栏：标题与关闭按钮。
2. 紧凑筛选栏：一行搜索框和自然宽度状态选择器；窄屏允许换行。
3. 可独立滚动的记录列表：使用行式卡片，而不是宽表格。
4. 底部分页栏：显示已加载数量与总数，存在下一页时显示“加载更多”。

每条记录包含：

- 第一行：状态徽标、可截断的项目标题、重命名入口。
- 第二行：业务摘要；爆款二创展示工作流阶段信息，一键成片展示产品名称等输入摘要。
- 第三行：更新时间与“继续创作”操作。

当前打开项目使用轻量背景和边框强调，不使用饱和色或额外装饰。

## 功能一致性

两边统一支持：

- 按项目名称搜索。
- 按状态筛选。
- 内联重命名，并展示保存中与失败状态。
- 继续创作并恢复对应项目。
- 服务端分页和追加加载。
- 首次加载、追加加载、空数据、请求失败和重试。
- 当前项目标识。

爆款二创继续使用现有项目列表、详情和更新接口。一键成片扩展列表接口的 `query`、`status`、`page`、`pageSize` 参数与分页响应，并让现有项目更新接口支持只更新标题的安全分支。所有查询与更新保持 owner 隔离。

## 数据与错误处理

- 筛选条件变化时重置到第一页，后续页面追加到当前列表。
- 重命名成功后刷新列表并同步当前项目标题；失败时保留编辑值并显示可重试错误。
- 打开项目时请求完整详情，失败不关闭抽屉，并在当前上下文显示错误。
- 一键成片更新标题沿用版本检查，避免覆盖并发编辑。
- 状态筛选只接受 OpenAPI 中声明的合法枚举值。

## 验证

- 为共享抽屉补充渲染与交互单测。
- 为一键成片列表查询、分页、owner 隔离和标题更新补充 API/Store 测试。
- 重新生成 OpenAPI 与前端 SDK。
- 运行相关单测、`make ci`、`bun run typecheck` 和 `bun run build`。
- 按仓库约束不运行 E2E；最终交由用户参考运行界面。

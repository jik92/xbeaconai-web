# Shadcn Compact Button 全局统一设计

## 背景

当前 Web 业务代码同时使用共享 `Button` 和原生 `<button>`。原生按钮分散在普通操作、图标操作、分页、标签、上传区、媒体缩略图、可点击卡片和时间线片段中，导致高度、字号、圆角、状态反馈与无障碍行为缺少统一入口。

## 目标

- 业务层不再直接渲染原生 `<button>`。
- 所有按钮语义统一通过 `web/components/ui/button.tsx` 的 shadcn 风格 `Button` 实现。
- 默认业务操作采用紧凑尺寸；特殊卡片、上传区和时间线只覆盖布局几何，不重新建立按钮视觉体系。
- 保留提交类型、禁用状态、ARIA 属性、键盘行为和事件传播等现有功能。
- 增加自动检查，防止业务代码重新引入原生 `<button>`。

## 边界

唯一允许的原生 `<button>` 是共享 `Button` 组件内部的底层 HTML 实现。第三方依赖内部实现不在仓库源码检查范围内。

以下业务场景全部纳入迁移：

- 主操作、次操作、危险操作和弹窗关闭操作
- 纯图标按钮、分页按钮、标签页和切换按钮
- 可点击媒体缩略图、素材卡片、选择卡片和上传触发区
- 时间线片段、播放控制和其他具备 button 语义的复合交互区

## 组件规格

共享 `Button` 继续负责焦点环、禁用状态、图标尺寸和基础排版，并提供明确的紧凑尺寸：

- `sm`：32px 高，用于绝大多数工具栏、表单和列表操作
- `icon-sm`：32px 方形，用于紧凑图标操作
- `default`：36px 高，用于需要略强层级的常规操作
- `icon`：36px 方形，用于常规图标操作
- `cta`：40px 高，仅用于确有主行动层级的场景

迁移时优先使用 `sm` 或 `icon-sm`。卡片、缩略图、上传区和时间线可通过 `className` 覆盖宽高、对齐和内部布局，但颜色、状态、焦点和按钮语义仍由共享组件承载。

变体以现有 `default`、`outline`、`ghost` 为基础；只有现有业务确实存在统一危险操作时才补充 `destructive`，不为单页创建私有变体。

## 迁移规则

1. 将业务 TSX 中的 `<button>` 替换为 `Button`，并从统一路径导入。
2. 保留显式 `type="submit"`；普通按钮依赖共享组件默认的 `type="button"`，避免表单误提交。
3. 保留 `disabled`、`aria-*`、`title`、`onClick`、`onPointerDown` 和拖拽相关属性。
4. 将能由 `variant`、`size` 表达的背景、边框、圆角、字号、内边距和 hover 样式从业务类中移除。
5. 复合交互区保留必要的布局类，不把非按钮容器强行迁移成按钮。
6. 不修改生成代码，不顺带格式化无关文件，不覆盖工作区已有改动。

## 防回归与验证

- 添加源码检查，扫描 `web/**/*.tsx` 中的原生 `<button>`，仅允许 `web/components/ui/button.tsx`。
- 运行针对该检查及共享 Button 的单元测试。
- 运行 `bun run typecheck` 和 `bun run build`。
- 运行项目完整基线 `make ci`；若遇到与本次无关的既有失败，单独记录并用变更范围内的检查证明本次迁移质量。
- 最终再次全量扫描，确认业务层原生 `<button>` 数量为零，并审阅差异确保事件、类型和可访问属性未丢失。

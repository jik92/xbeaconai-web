# 脚本二创新版设计

## 目标

在现有【脚本二创】旁新增独立菜单【脚本二创【新】】，用于和老版流程对比。新版项目、任务和历史记录与老版完全隔离，不迁移或混合展示老版数据。

新版采用四阶段工作流：

1. 上传配置
2. 生成分镜稿件
3. 分镜校对
4. 合并生成

## 架构

采用“独立新版流程 + 复用底层生成能力”：

- 新建独立页面、路由、项目类型、持久化结构、API 契约、Worker Job 和项目历史。
- 复用现有商品、人像、音色选择器，以及爆款二创已有的视频生成、轮询、版本选择、排序、FFmpeg 合片和下载能力。
- API Server 只负责鉴权、用户资源隔离、参数校验、持久化和 BullMQ 投递。
- Worker 执行脚本解析、九宫格生成、单格图片重生成、视频生成和合片，并将阶段、进度、结果和错误回写 SQLite。
- 所有提交使用持久化状态和幂等键，支持重试、取消、重复投递和 Worker 恢复。

## 阶段一：上传配置

### 输入

- 必填：一个 `.txt` 或 `.md` 脚本文档、一个商品。
- 选填：人像、音色。
- 不支持 DOCX、PDF 或扫描件 OCR。

脚本文档沿用浏览器直传私有 TOS 的素材上传方式，项目只保存当前用户拥有的素材 ID。Worker 使用短期访问地址读取文本，并校验扩展名、MIME、编码、大小和非空内容。

### 脚本解析

- 固定调用 `gpt-5.6-sol`，不可用或失败时明确报错并允许使用同一模型重试，不自动降级。
- 输出结构化分镜：序号、口播文案、画面描述、动作、景别与运镜、预计时长、商品与人物要求。
- 模型先按内容自然拆分；超过 9 个时自动合并压缩到最多 9 个并保留完整原稿信息，少于 9 个时保留实际数量。
- 用户可以逐分镜编辑字段、保存、整体重新生成。确认满意后进入下一阶段。

## 阶段二：生成分镜稿件

- 将已确认分镜、商品图和可选人像图组合成一致性提示词。
- 固定调用 `gpt-image-2` 生成一张 3×3 九宫格图片；失败时只允许同模型重试。
- 有效分镜按从左到右、从上到下排列。少于 9 个时，剩余位置生成明确的中性空白占位格，不放业务画面。
- 支持整张九宫格重新生成并保留历史版本，不在该阶段单独重生成某格。
- 用户选择并确认一个九宫格版本后，系统按固定网格切成 9 格，只为有效分镜创建裁剪图。

## 阶段三：分镜校对

使用表格呈现，一个有效分镜一行。每行包含：

- 分镜序号和文案摘要
- 当前参考图及其版本
- 视频生成参数
- 生成任务状态
- 成功视频版本预览与选择
- 单行生成、重试和参考图操作

视频参数先配置一次全局模型、比例、分辨率和时长，每行可独立覆盖。参考图默认采用九宫格裁剪图；每行可从本地上传或素材库选择替换图，也可调用 `gpt-image-2` 单独重新生成。

支持逐行与批量生成视频。批量操作默认只处理未成功或用户明确选择的分镜，已成功分镜不会被重复提交或重复扣费。只有所有有效分镜都选定一个成功视频版本后，才能进入下一阶段。

## 阶段四：合并生成

- 用户可拖拽调整分镜顺序，并为每个分镜选择任一成功的视频版本。
- 提交后由 Worker 使用 FFmpeg 统一媒体参数并按顺序合片。
- 结果页提供成片预览和直接下载，不自动触发下载。
- 合片失败时保留当前顺序和视频版本选择，只重试合片。

## 状态与依赖失效

页面使用现有 `workflow-header` 展示四阶段。阶段不可向前跳过，已完成阶段可返回查看和修改。

修改已确认的上游数据会使对应下游结果失效：

- 修改脚本解析结果：九宫格、裁剪图、分镜视频和合片失效。
- 更换九宫格版本：裁剪图、基于裁剪图生成的视频和合片失效；使用用户替换参考图生成的视频可按引用关系判断。
- 更换某行参考图或视频参数：该行后续生成不复用旧幂等结果，已选视频仍保留为历史版本。
- 修改排序或已选视频版本：只使合片结果失效。

执行失效清理前必须向用户明确展示影响并取得确认。物理素材遵循引用关系和既有清理策略，不直接删除仍被历史记录引用的 TOS 对象。

## 界面

- 菜单【脚本二创【新】】位于【创作工作流】，紧邻老版【脚本二创】。
- 页面标题只保留主标题，不增加副标题或说明性文案。
- 上传阶段采用左侧紧凑配置栏和右侧解析结果工作区，复用现有上传与素材选择组件。
- 九宫格阶段提供完整图片预览、版本列表、重新生成和确认操作。
- 分镜校对复用共享表格视觉规范，内容区独立滚动；行内允许参考图、视频预览和紧凑参数操作。
- 合并阶段复用爆款二创的排序、版本选择、媒体预览和下载能力。
- 独立项目历史抽屉支持搜索、重命名、继续和状态筛选。
- `1440×900` 展示完整工作台；`1024×768` 隐藏次要标签并压缩工具栏，同时保持主要表格操作可用。

## 错误与能力状态

- `gpt-5.6-sol`、`gpt-image-2` 或视频 Provider 未检测通过时，菜单入口仍展示，但相关提交不可用并显示真实原因。
- 不静默切换 Provider、模型或 Mock；所有任务记录实际 Provider、模型和来源。
- API 错误沿用 `code`、`message`、`retryable`、`requestId` 结构。
- 文档错误、模型输出结构错误、九宫格切图失败、单格生成失败、视频任务失败和合片失败均可在所属阶段独立重试。

## 验证

- 单元测试：TXT/MD 校验、文本解码、分镜解析结构、最多 9 镜压缩、空白格、网格切图、参数继承与覆盖、依赖失效、幂等键和合片排序。
- 集成测试：鉴权和用户资源隔离、API 状态迁移、BullMQ 重试/取消/恢复、批量与逐个视频生成、版本选择及合片失败恢复。
- API 变化后重新生成 OpenAPI 与前端 SDK，并运行相关测试、`bun run db:check`、`make ci`、`bun run typecheck` 和 `bun run build`。
- 为新四阶段关键流程添加 E2E 用例，但默认不运行；只有用户明确要求时执行 `bun run e2e`。

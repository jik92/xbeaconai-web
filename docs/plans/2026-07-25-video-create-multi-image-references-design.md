# 一键成片多图片参考修复设计

## 目标

修复分镜【AI生成视频素材】在已选择人像时跳过商品图片的问题。单个分镜默认绑定项目中的人像、全部商品图片和音频参考，并保证弹窗、内部 API、BullMQ 任务与 Seedance 上游 `content` 的素材顺序完全一致。

## 绑定与编号

- 默认附件按人像、商品图片、音频的顺序构建；项目当前最多包含六张商品图片。
- 图片使用 Seedance 可识别的 `Image1`、`Image2` 顺序标签，视频和音频分别使用 `VideoN`、`AudioN`。
- 提示词使用对应的 `@ImageN`、`@VideoN`、`@AudioN` 引用。用户增删附件后自动重排同模态编号并同步提示词，避免标签与上游素材位置错位。
- 支持最多九张图片、三个视频、三个音频，所有模态合计不超过十二个素材；继续执行现有单文件大小和总大小限制。

## 数据流

服务端草稿接口返回全部默认附件和按顺序构建的最终提示词。前端在弹窗中展示附件、标签和完整提交 JSON，提交时传递有序引用列表。任务参数保存有序素材引用及人像位置，Worker 按该顺序完成私有素材暂存和公共人像引用组装，Provider 将相同顺序写入 `extra_body.content`。

Mock 模式保留，使用同一套草稿和任务参数，但继续绕过真实素材暂存与付费 Seedance 调用。

## 校验与错误处理

- API 校验素材归属、MIME 类型、每种模态数量、总数量、单文件大小、总大小和标签连续性。
- 每个提交附件必须在提示词中有对应 `@标签`，提示词中也不能存在未绑定标签。
- 不再将人像与商品图片视为互斥，也不再拒绝第二张图片。
- 不符合约束时返回现有结构化 422 错误，不创建任务。

## 测试

- 提示词与引用校验覆盖多图片、人像与商品图共存、数量上限和未解析标签。
- 草稿行为覆盖全部商品图片均进入附件列表。
- Worker/Provider 覆盖多张 `reference_image` 的顺序不变。
- 更新 OpenAPI、生成 SDK、类型检查、单元测试和生产构建；不运行 E2E，不调用真实付费 Seedance。

# 密钥导入导出设计

## 目标

密钥管理支持管理员导入和导出 `.env.key`。导入只补充当前未配置的密钥，任何已有密钥都不得被批量导入覆盖；导出用于备份和环境迁移，包含当前已配置密钥的真实值。

## 导入规则

- 继续接受现有 `.env.key` 格式和 64KB 限制。
- 文件中的非空受支持字段，仅在数据库中不存在对应密钥时写入。
- 数据库中已有的密钥无论导入值是否不同都跳过。
- 文件中的空值、未提供字段和未知字段不修改数据库。
- 响应继续返回 `updated`、`skipped` 和 `ignored`，供页面显示导入摘要。
- 仅失效本次实际新增密钥所属 Provider 的 Doctor 结果。

## 导出规则

- 新增管理员专用导出接口，使用现有 Bearer Token 和管理员校验。
- 服务端从加密 Store 解密当前已配置值，使用现有 `serializeEnvKey` 生成完整字段顺序的 `.env.key`；未配置字段保持空值。
- 响应为 UTF-8 文本附件，文件名 `.env.key`，并设置 `Cache-Control: no-store`。
- 密钥不得写入日志、错误信息、URL、数据库以外的新持久化位置或普通列表接口。

## 页面交互

在密钥管理工具栏的导入按钮旁增加“导出 .env.key”按钮。点击后通过生成的 API SDK取得文件内容并触发浏览器下载；导出期间禁用按钮并显示加载状态，失败使用现有 toast 错误样式。

不新增副标题、说明文案、卡片或新的视觉模式。

## 验证

- Store 测试覆盖仅新增缺失值、保留已有值和真实值导出。
- API/OpenAPI/SDK 覆盖管理员导出和导入结果契约。
- 管理页面测试覆盖导出入口和生成 SDK 的使用。
- 运行 `bun run api:spec`、`bun run api:generate`、相关单元测试、`make ci`、`bun run typecheck` 和 `bun run build`；按仓库规则不运行 E2E。

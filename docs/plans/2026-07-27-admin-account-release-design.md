# 管理后台批量释放账号设计

## 目标

在管理后台用户管理页增加当前页批量选择和“释放账号”操作。释放成功后，账号及其所有本地、SQLite、TOS 和 Ark 自建虚拟人像资源都被物理删除，手机号可以重新注册。

## 安全边界

- 仅允许管理员调用。
- 管理员账号永远不可选择或释放。
- 仅允许释放已注销账号；正常账号必须先注销以撤销会话和阻止新任务提交。
- 存在排队、运行或等待外部 Provider 的非终态任务时拒绝释放，避免 Worker 在删除期间继续写入。
- 确认 Dialog 明确列出目标账号和不可恢复影响，并要求输入“释放账号”。
- 单次最多释放 100 个去重账号；用户管理当前每页最多 25 个。

## 用户界面

用户表第一列增加复选框。管理员、正常账号和待设置密码账号不可选；表头复选框只选择当前页全部可释放账号。切换页码、搜索条件或状态筛选时清空选择，避免删除不可见目标。

工具栏增加“释放账号（N）”危险操作按钮，仅在存在选择时启用。确认 Dialog 使用现有 title-only Dialog 视觉规范，展示所选账号、删除范围、不可恢复警告和确认输入。提交期间禁止关闭和重复提交。

批量接口逐账号返回结果，允许部分成功。成功账号从列表消失并清除选择；失败账号保留，界面展示每个账号的具体失败原因。

## 服务端流程

新增管理员批量接口 `POST /api/admin/users/release`，请求体为 `userIds`，响应包含逐账号的成功摘要或结构化错误。

每个账号按以下顺序处理：

1. 预检账号存在、已注销、非管理员且无非终态任务。
2. 收集自建虚拟人像 Ark Asset ID、用户 Ark Asset Group、所有 TOS 对象键、任务暂存键、本地上传和生成物路径。
3. 删除 Ark 自建虚拟人像资产，再删除该用户的 Ark Asset Group。远端已不存在视为成功，其他错误终止该账号释放。
4. 删除 TOS 中以用户 ID 开头的全部对象，并删除数据库记录中的额外暂存/生成键；删除后重新列举验证为空。
5. 删除受数据目录约束的本地上传和生成物文件。
6. 在一个 SQLite immediate transaction 中按外键依赖顺序删除所有账号关联记录，最后删除用户行。

Ark 或 TOS 删除失败时不删除 SQLite 账号，账号保持已注销以便重试。批量处理按账号顺序执行，单个账号失败不阻断其他账号。

## 数据范围

SQLite 删除覆盖：短信验证码、密码设置令牌、会话、通知、充值和管理员充值记录、余额扣费与退款、偏好与输出文件夹默认值、素材文件夹、素材与商品、自建虚拟人像及 Ark 分组、任务、任务暂存清理记录、Provider 审计、生成物、广告脚本项目及版本、一键成片项目及分镜/脚本/素材版本，以及用户本身。全局 Provider 密钥不删除，只清空其 `updated_by_user_id` 审计引用。

TOS 删除覆盖：`${userId}/` 前缀下全部对象，以及该用户任务 `staging_keys_json`、素材和 artifact 表中记录的所有额外对象键。分页列举和删除必须处理超过单页的对象集合。

本地文件删除只允许在 `YAOZUO_DATA_DIR/uploads` 和 `YAOZUO_DATA_DIR/results` 下解析出的安全路径，禁止越界删除。

## 错误与幂等

- 已被释放的目标返回“账号不存在”，不伪装成功。
- Ark/TOS 的 NotFound 视为已删除；鉴权、限流和网络失败保留账号并返回可重试错误。
- 数据库删除前再次检查账号状态和非终态任务，减少检查与执行之间的竞态。
- 每个成功结果返回删除的 Ark 资产数、TOS 对象数和数据库账号 ID，便于管理员核对。
- 服务端日志只记录管理员 ID、目标 ID、阶段和数量，不记录凭证或签名 URL。

## 验证

- Store 测试为一个账号创建每类关联记录，释放后逐表确认无残留，并确认其他账号和全局配置不受影响。
- 服务测试覆盖 Ark/TOS 删除顺序、分页前缀删除、NotFound 幂等、外部失败保留数据库、非终态任务拒绝和管理员保护。
- API 测试覆盖管理员鉴权、请求上限、部分成功响应和 OpenAPI 契约。
- 前端测试覆盖可释放行选择、当前页全选、切换筛选清空、确认短语和部分失败呈现。
- 生成 OpenAPI/SDK，并运行 `make ci`、`bun run typecheck`、`bun run build`；按仓库规则不默认运行 E2E。

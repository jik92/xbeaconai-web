# 公共保存位置选择器设计

## 背景

视频分割任务已经可以选择保存位置，但通用任务表单、视频混剪、视频提取和视频编辑器导出各自维护文件夹列表与选择控件。用户无法在创建任务时直接创建一个新的默认文件夹，重复实现也容易造成默认选择和刷新行为不一致。

## 目标

- 抽象一个公共的保存位置选择组件，供所有创建生成任务以及视频提取、视频导出流程复用。
- 文件夹按父子层级展示，并明确标记默认文件夹。
- 用户可以在选择区域内新建根级文件夹。
- 新文件夹创建成功后自动设为默认、自动选中，并刷新共享文件夹缓存。
- 加载、创建和设默认失败时给出明确反馈，不关闭当前任务弹窗。

## 方案

新增 `SaveLocationPicker` 受控组件。页面只负责保存当前选中的文件夹 ID；组件通过 React Query 获取文件夹数据，负责默认值初始化、层级排序、新建和设默认的完整流程。这样所有入口共享同一查询键，任一入口创建文件夹后，其他入口会读取相同的最新缓存。

组件保留紧凑的原生选择框外观，在旁边提供“新建文件夹”操作。点击后显示一个紧凑的行内名称输入框和确认/取消按钮，不使用浏览器 `prompt`。创建时禁用重复提交；成功后依次将新文件夹设为默认、刷新查询缓存并调用 `onChange(newFolder.id)`。

## 接入范围

- `ModulePage` 通用新建任务弹窗，包括视频分割等声明了 `saveLocation` 的任务。
- 视频混剪新建任务。
- 视频提取/分享内容导入。
- 视频编辑器导出视频。

页面不再自行获取、排序或初始化保存文件夹；提交的数据字段保持现有 API 契约不变。

## 错误与边界

- 无文件夹时显示不可提交的占位项，并保留新建入口。
- 初次加载完成且当前值为空或已失效时，优先选择默认文件夹，否则选择列表首项。
- 空白名称不提交。
- 创建成功但设默认失败时保留新文件夹并选中，同时显示默认设置失败；用户仍可继续任务。
- 组件卸载或弹窗关闭不保留未提交的新建名称。

## 验证

- 单元测试覆盖默认初始化、层级展示、新建后选中并设为默认、失败反馈。
- 接入测试证明通用任务表单使用公共组件并保持原有字段值。
- 运行相关 Bun Test、`make ci`、`bun run typecheck` 和 `bun run build`；按仓库要求不运行 E2E。
